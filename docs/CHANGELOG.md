# 更新日志

## 1.0.4.0（2026-11-14）

- **新增: 性能模式 (风扇降噪)**: 拯救者三档 (野兽/均衡/安静, GameZone WMI 即 Fn+Q 官方接口) 与 Windows 电源档 (最佳能效/平衡/最佳性能, powercfg 叠加层, 免管理员)
- **托盘直达切换**: 托盘右键新增「性能模式」子菜单——后台直接切档, 不用打开主窗口; 打开菜单时显示当前档位对勾, 拯救者接口首次懒探测

- **新增: 性能模式 (风扇降噪)**: 设置页新增「性能模式」卡片——拯救者三档 (野兽/均衡/安静, GameZone WMI 即 Fn+Q 官方接口) 与 Windows 电源档 (最佳能效/平衡/最佳性能, powercfg 叠加层, 免管理员)
- **夜间自动降噪联动**: 开关开启后, 切入夜间远控自动降到「安静档 + 最佳能效」, 回本机自动还原切换前的档位; 快照仅内存保存, 接口不可用时跳过并记录原因, 绝不阻塞守护流程
- 拯救者接口探测只读 (Get 不 Set); 权限不足/非拯救者机型时按钮禁用并给出明确原因提示
- 电源档 GUID 运行时从注册表按微软固定前缀自动发现 (实测联想 83F4 的能效/性能档尾号与文档不同, 硬编码会失败); 经系统级实测: 平衡/最佳能效切换成功、免管理员, 拯救者 WMI 非提权被拒 (程序内降级提示)

## 1.0.3.0（2026-11-11，2026-11-12 增补）

- **修正 1.0.2.0 的启动模式启发式缺陷**: 启动恢复改按"内屏是否活跃"判断——全部活跃显示器均为虚拟屏（真息屏远控/无头）才恢复夜间模式；内屏活跃（人在本机）一律本机启动，绝不切 ExternalOnly。虚拟主屏标记会跨会话残留，不能作为远控依据
- **本机模式清理虚拟屏先切回内屏**: 上次夜间会话残留的虚拟主屏不再被"直接移除引发拓扑回退乱串"，先一次干净的内屏切换再清理
- **代理守护双模式**: 端口模式（AgentPort>0，本地监听型代理）与进程模式（AgentPort=0，云端中继型代理如向日葵——本地无监听端口，进程存在即健康）；拉起前查同名进程存在则不重复拉起（消除僵尸进程堆积）
- **CheckNowAsync 正规异步入口**: 守护页等待真实完成；托盘"立即检查"改为即发即忘（巡检含修复重试时不再阻塞 UI 线程）
- **设计合规清理**: 死配置字段 ToastOnOkEvery / VddExePath 移除；VddController 死计数机制 `_activeDisplays` 移除（只写从不读）；设置页重复的 OpenRGB 按钮合并
- **品牌全表面统一**: 窗口标题/托盘/关于页/程序集统一为预留名"QuietScreen 屏息"；托盘悬浮提示内容不变时不再重复调用原生接口
- **修复: OVERLAPPED 热路径重写**（驱动通信层）: DeviceIoControl/GetOverlappedResult*/CancelIoEx 签名改为 IntPtr 直传，OVERLAPPED 位于显式原生内存（心跳路径常驻复用、通用路径按调用分配），生命周期严格覆盖异步 IRP——消除 ref 编组栈副本在异步完成时踩栈的理论风险。经 --selftest 实测验证（版本 IOCTL + 心跳 2.5 秒实跑，11/11 通过）
- 新增: **远控环境体检**（守护页，只读）——检查"重启后能否顺利连回"的隐藏前提：Windows 自动登录 / 屏保密码锁定 / 待重启的更新 / 虚拟屏驱动 / 防睡眠，异常项给出修复指引；同步纳入 --selftest
- 打磨: 虚拟屏创建的 GDI 物化等待窗口 30 秒 → 50 秒（实测"刚移除又重建"场景物化需 ~30 秒，旧窗口刚好超时导致误报"屏幕未出现"）
- 打磨: 钩子回调与 WM_HOTKEY 路径的队列写入改为 TryAdd（队列满时丢弃而非阻塞——消除低级键盘钩子卡死全系统键盘输入的理论风险）
- 打磨: 自动缩放窗口期对设置页先优雅关闭再结束（防误杀）；托盘"重启代理"加确认对话框；本机启动跳过预建时写日志（可观测）
- 上架: 应用图标定稿（几何 Q）、商店身份与显示名对齐预留名、包内清单四字段与 Partner Center 解包实测一致

## 1.0.2.0（2026-11-11）⚠️ 已知缺陷：启动启发式误判（见 1.0.3.0）

- 修复: 息屏远控状态下重启应用 → 约 20 秒后远端黑屏。原逻辑启动一律进"本机模式"，巡检会把远端正在显示的虚拟屏移除。本版启动按"主屏是否虚拟"恢复模式
- 深层机制: Windows 会按显示器组合回放记忆布局——历史中"虚拟屏为主屏 + 内屏熄灭"的布局在新屏加入时被回放（1.0.3.0 的本机不预建恰好绕开了该触发条件）
